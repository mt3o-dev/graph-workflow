# Deferred verification (Phase 6 — Tauri shell + e2e scaffold)

This project's build machine is **Node 26 + pnpm only**: no `cargo`/`rustc`,
no Docker, no GPU, no microphone, no network keys (tech-stack.md
"Environment constraints"; plan.md "Environment contract"). Everything in
this document was authored with care — types checked where possible, config
schemas hand-verified against the Tauri 2 docs — but could not be executed
here. Run these on a machine that has the Rust toolchain (and, where noted,
a mic/Docker/GPU) before relying on them.

## What is deferred, and why

| Area | Why it can't run here | What was done instead |
| --- | --- | --- |
| `cargo check` / `cargo build` on `src-tauri/` | No `cargo`/`rustc` on this machine | Hand-verified `Cargo.toml`, `tauri.conf.json`, `src/main.rs`, `src/lib.rs`, `capabilities/default.json` against the Tauri 2 schema/docs; kept the Rust surface minimal (2 commands + window bootstrap) to shrink the blast radius of any mistake |
| `pnpm tauri build` (full bundle) | Needs `cargo`, platform bundling toolchain (WebKitGTK etc. on Linux), and produces platform installers | Confirmed `pnpm tauri --version` runs (CLI itself works via pnpm); confirmed the frontend half (`TAURI_BUILD=1 pnpm build`) produces `build/` matching `frontendDist: "../build"` in `tauri.conf.json` |
| `pnpm tauri build --debug` (for e2e) | Same as above | N/A — this is the artifact e2e needs; see e2e/README-e2e.md |
| e2e suite (`pnpm test:e2e`) | Needs `tauri-driver` (`cargo install tauri-driver`) and a debug Tauri binary | `e2e/preflight.ts` checks both and exits 1 with an actionable message instead of letting wdio hang; verified this skip path runs cleanly here. Specs (`e2e/smoke.e2e.ts`, `e2e/live-session.e2e.ts`) are written and documented but unexecuted |
| Live microphone capture | No mic/audio hardware exposed to this environment | Out of scope for this phase entirely — no code in this phase touches audio capture (that's the STT adapters from Phase 3, which are mock/fixture-driven per plan.md risk 1) |
| Tauri icon bundling for real platform targets | `src-tauri/icons/*.png` were generated by `scripts/generate-tauri-icons.ts` as solid-color placeholders (valid PNGs, so `tauri build` won't choke on missing/corrupt files) — they are not a designed icon, and no `.ico`/`.icns` were generated (those need the Tauri CLI's image pipeline) | Documented here; before a real bundle build, run `pnpm tauri icon path/to/real-icon.png` (>=1024x1024 source) to regenerate all platform formats properly |

## Exact commands to run elsewhere

On a machine with the Rust toolchain installed (see
https://v2.tauri.app/start/prerequisites/ for OS-specific system deps):

```sh
# 1. Rust-side sanity check
cd dogfood/interview-copilot/src-tauri
cargo check

# 2. Full debug build (also what e2e needs)
cd dogfood/interview-copilot
pnpm install
pnpm tauri:build -- --debug   # sets TAURI_BUILD=1, builds Svelte to build/, then cargo builds the shell

# 3. Real app icon (replace the placeholders committed in this phase)
pnpm tauri icon path/to/real-icon.png

# 4. Release bundle
pnpm tauri:build

# 5. E2e
cargo install tauri-driver
pnpm test:e2e   # runs e2e/preflight.ts, then wdio against tauri-driver
```

On a machine with mic hardware and either a local WhisperLive-compatible
Docker+GPU server or OpenAI/Anthropic API keys (for the live adapter paths
built in Phase 3 — not part of this phase):

```sh
IC_answer__adapter=anthropic-haiku IC_stt__adapter=openai-stt pnpm dev
# or point stt.adapter at a running WhisperLive server for the local path
```

## What is NOT deferred — verified here

- `pnpm typecheck && pnpm test && pnpm build` — green, unaffected by this
  phase's changes (adapter-static is opt-in via `TAURI_BUILD=1`; see
  `vite.config.ts`).
- `TAURI_BUILD=1 pnpm build` — green; produces `build/index.html` +
  `build/_app/` (SPA fallback via `@sveltejs/adapter-static`).
- `pnpm tauri --version` — the Tauri CLI itself runs fine under pnpm/Node
  (it's a thin binary wrapper; it doesn't need the Rust toolchain to report
  its version).
- `pnpm test:e2e` — confirmed it exits 1 with a clear, actionable skip
  message (missing `tauri-driver` + missing debug binary) rather than
  hanging or crashing opaquely.
- All `tauri.conf.json` / `capabilities/default.json` JSON is valid and was
  cross-checked field-by-field against the Tauri 2 config schema
  (`https://schema.tauri.app/config/2`) referenced in the file itself.
